# Phase 4, S11: VILMA2 row order (2026-10-30)

`$G = /work/ba1442/robinson/kryos-gate`. Bug: kryos's Gauss grid ascends in latitude, VILMA2's state is north first; the passthrough
copied the rows unreversed both ways, so the kryos side of VILMA2 was mirrored north-south consistently except what VILMA2 reads in real
geography (3-D viscosity): the NH loads sat on the ~60 S viscosity (G2b diagnosis, `p4-g2b.md`).

Fix: vilma2 `host-orient` (not pushed): f1ceee3 (passthrough reverses the rows of an ascending Gauss host both ways: `gauss_axes_rows`,
`rows_copy`, `se%host_rows`; host-grid ocean function `se%C`; `test_host_orient`), c17d513 (the legacy Gauss-grid reader takes the row
order from the file's lat axis, stops without axes; `test_drive` with ascending files). kryos `vilma-orient` (not pushed): de22e3e (the
adapter exports `se%dz_bed`, `se%dz_ss`, `se%C`, never `se%gg`), cc6fb9e, 82b4fe3 (G2a: compare aligned by lat; lon-lat variant),
p4-g2b merged, S11 scripts, `g3_budget.jl` aligned by lat (4f34a0b).
Stack S11 = S10 + vilma2 c17d513 + kryos 3607918 (`tools/setup_S11.sh`, bundles `$G/bundles/{vilma2-host-orient,kryos-vilma-orient}.bundle`;
fesm-utils, yelmo and the other packages as S10, not rebuilt). Scripts `tools/levante/{gate_S11,compare_S11,g2a,g2b}.sh`; scripts fixed
after the stack was set up run from `$G/s11/tools`. Reports `$G/reports/S11/`.
**Every VILMA2 restart written before S11 holds mirrored state and is invalid** (VILMA2 stops on its reference unless it is north-south symmetric).
